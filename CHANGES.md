## Price Books & Carton Mapping — built from scratch

Both had Prisma models but **no module existed at all** despite being
explicitly requested. Added:
- `catalogue/price-books` — CRUD, item management (`POST/PATCH/DELETE
  /catalogue/price-books/:id/items[/:itemId]`), duplicate-name prevention.
- `catalogue/carton-mappings` — CRUD, prevents a product being mapped as a
  carton of itself, prevents duplicate carton/child pairs (also enforced at
  the DB level now — see schema changes).
- Both wired into `catalogue.module.ts`.

## Audit logging — real bug fixed

`ProductAuditService.log()` was writing through a **separate Supabase REST
client**, while product history reads (`getProductHistory`) read through
Prisma. This meant:
- Audit writes were not part of the same DB transaction as the product
  change — a rollback could leave the audit write already committed via
  Supabase (or vice versa lose it), i.e. no atomicity.
- The app **crashed on boot** if `SUPABASE_URL` / `SUPABASE_ANON_KEY` weren't
  set (non-null assertions on a client created eagerly at import time).
- `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `DATABASE_URL` were being printed
  to the console in `main.ts` / `config/supabase.ts` — a secret leak.

Fixed: `ProductAuditService` now writes via Prisma and accepts the active
`tx` from the calling transaction, so audit rows commit/rollback atomically
with the product change. All five call sites in `products.service.ts`
(create/update/delete/restore/CSV import) now pass `tx`. The console logs
were removed. `config/supabase.ts` is kept (unused) for any future
Supabase-specific feature, but no longer runs at import time.

## Prisma schema

- Added indexes on `products` FK columns (`category_id`, `brand_id`,
  `supplier_id`, `department_id`), `status`, `deleted_at`, `name`.
- Added indexes on FK columns across `inventory`, `inventory_logs`,
  `product_inventory`, `product_audit_logs`.
- Added a DB-level `@@unique([carton_product_id, child_product_id])` on
  `carton_mappings` (was only checked in application code — race condition
  under concurrent requests).
- Added a DB-level `@@unique([price_book_id, product_id])` on
  `price_book_items`, plus `onDelete: Cascade` so deleting a price book
  correctly cascades its items.
- **This requires a migration** — run `npx prisma migrate dev` after
  reviewing the diff.

## Known gaps / things to double check yourself

- `products.name` is required in `CreateProductDto` now (was optional) —
  intentional (a nameless product doesn't make sense, and CSV import already
  required it), but confirm this matches your existing data / any client
  code that creates products without a name.
- Price Books and Carton Mappings have no `deleted_at` column in the schema,
  so their delete endpoints are **hard deletes**, not soft deletes. Add a
  `deleted_at` column + migration if you want soft delete there too.
- I could not run the test suite (`products.controller.spec.ts`,
  `products.service.spec.ts`) — they may need updates to match the new
  required `name` field and new constructor/DTO shapes.
